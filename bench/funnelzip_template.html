FunnelZip

Every idea we tried becomes a lens that guesses the next bit. A funnel of mixers learns, bit by bit, which lenses to trust. Nothing is chosen by hand, no recipes are stored, and the decoder replays the same funnel.

Lessons from the experiments: (1) an equation should predict, not print exactly; a near miss still saves bits. (2) Don't pick one method; let them all vote, weighted by how right each one has been lately.

Repeats of repeats

A repeat gets one equation; repeated repeats get one rhythm

Echo finds a repeat, but loses it at the first changed byte. Rhythm keeps the beat: Listen hears the period (a log line, a music bar, a video frame), and the lens reads "the same moment one period ago". For signals it also re-plays the leftover of the previous repeat with a learned gain, so a bar played louder or softer is still "the same equation".

File or pixels?

Compress where the structure lives

An image file is not its pixels: PNG has already scrambled the positions with deflate, and JPEG has already turned them into cosine waves. FunnelZip on the file finds almost nothing. On the decoded pixels its grid and rhythm lenses see rows, columns and frames again. For JPEG, the right level is in between, its cosine coefficients (Dropbox's Lepton gets ~22% there, bit-exact).

Is anything lost?

Pure lossless: every byte comes back

For every file: compress, decompress, then compare the SHA-256 fingerprint and every single byte with the original. Nothing is approximated anywhere in FunnelZip. (The only lossy parts of this whole project were the early "cosine wave" image/audio/video tests and the MP3/JPEG/H.264 reference codecs.)

Your idea: convert it first, undo it after

Reshape the file where the lenses can see it, then reverse it exactly

Turning a file into "pure 0s and 1s" adds nothing: FunnelZip already reads every file bit by bit. What helps is reshaping: putting similar things next to each other, coding the reshaped file, and undoing the reshape on decode. Listen now tries each reshape on a sample and keeps one only if it wins.

before (no reshape)afterbest existing

Reshapes: colour transform (R−G, B−G, so the three colours stop repeating the same brightness); planar (all red, then all green, then all blue); prediction residual (each pixel minus its JPEG-LS guess, which turns smooth gradients into zeros); caps + words for text (upper case → marker + lower case, common words → 2-byte codes). For JPEG files, telling FunnelZip the coefficient layout instead of guessing is also a reshape.

Speed round

Faster — and the files got smaller, not bigger

Goal: 1+ MB/s at the same ratio. We profiled the C core and fixed what the profile showed. The JPEG Huffman layer moved to C. Then two things made files both faster and smaller: Listen now drops lenses a file can't use, and JPEG frequency planes get their own models running in parallel.
