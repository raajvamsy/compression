EquaFile · follow-up test

Tiny loops, simple equations,
best one for each piece

The idea: keep the loop count to a single digit, use only simple equations, and for each part of the file pick whichever works best. Built and tested on every sample.

What was built (V8)

One piece of the file = one small recipe

For every position in the file, the encoder tries all 524,288 small recipes and keeps the one that prints the longest run of bytes. Where nothing fits, the byte is stored as is.

The catch

The menu is tiny compared with what files contain

Small loops and simple equations mean few possible recipes. Many of them even print the same thing (short cycles), so only different 9-byte pieces can be printed at all.

Measured

How much of each file the recipes could print

Teal = bytes printed by an equation, grey = bytes that had to be stored as they are. On ordinary files 69–86% of the matches are just 3 bytes long, coincidences that save only 4 bits each. The long ones are mostly runs of spaces.

Size

Result: bigger than the file on most samples

Each literal costs 9 bits (a flag plus the byte), so files the recipes can't print grow. Compare with the best of the earlier equation types and with today's best compressor.

Sub-equations with the same loop count

Feeding the recipes back in: every level grows

The list of recipes for typing.py was encoded again with the same small recipes, then again. The list itself looks random, so each round adds about 11%.

So what's right and what isn't

Takeaways

✓ "Best approach per piece"

This part is right, and it is where every win came from. Patterns get an equation, text gets prediction. Auto mode already picks the best method per file.

✗ "Small loop + simple equation"

It makes the recipe cheap, but it also makes the menu tiny. Real files are almost never on the menu, so most bytes fall back to literals.

✗ "Same trick on the sub-equations"

A list of recipes has no pattern left, so encoding it again grows it ~11% per level.

→ The rule underneath

A recipe can only be shorter than what it prints if the data is one of the few things the recipes can print. Short recipes mean few recipes.
